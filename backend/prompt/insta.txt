### `src/routes/instagram.routes.js`

The file contains these routes:

1. `GET /connect`
   - Generates a cryptographically random OAuth `state` using `node:crypto`.
   - Saves the state in `req.session`.
   - Redirects to Instagram authorization.

2. `GET /callback`
   - Handles Instagram's OAuth callback.
   - Validates `code`, `state`, and authorization errors.
   - Exchanges the authorization code server-side using Axios.
   - Stores the access token and Instagram user ID in the server session.
   - A later correction fetches the authenticated profile from the `/me` endpoint and stores that ID and username in the session.

3. `GET /me`
   - Uses the session access token.
   - Calls the official Instagram Graph API.
   - Returns `connected`, `igUserId`, and `username`.
   - Does not return the access token.

4. `POST /posts`
   - Reads `imageUrl` and `caption` from the JSON request body.
   - Checks that the user has an Instagram token and ID in their session.
   - Validates the HTTPS image URL and caption.
   - Inserts a pending post into SQLite.
   - Creates an Instagram media container.
   - Publishes the media using Meta's Content Publishing API.
   - Updates the SQLite record to `published` or `failed`.
   - Returns the published media ID after successful publishing.

5. `GET /posts`
   - Intended to return the latest 10 records from SQLite.
   - This route may not have been added and tested yet. Verify before assuming it exists.

### Database configuration

File: `src/config/database.js`

The database uses `better-sqlite3`:

```js
import Database from "better-sqlite3";

const db = new Database("social-poster.db");

db.pragma("journal_mode = WAL");

db.exec(`
  CREATE TABLE IF NOT EXISTS instagram_accounts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ig_user_id TEXT UNIQUE NOT NULL,
    username TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );

  CREATE TABLE IF NOT EXISTS posts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    image_url TEXT NOT NULL,
    caption TEXT NOT NULL,
    container_id TEXT,
    media_id TEXT,
    status TEXT NOT NULL DEFAULT 'pending'
      CHECK (status IN ('pending', 'published', 'failed')),
    error TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
  );
`);

console.log("SQLite database connected");

export default db;
```

The database file is `social-poster.db` in the backend working directory. Confirm the actual path before changing database commands.

## 7. Previous Errors and Lessons

### `ReferenceError: session is not defined`

```js

```

### `Invalid OAuth state`

Resolved by configuring session cookies and starting OAuth from the ngrok HTTPS URL. Connect and callback must use the same browser session.

### `Connect Instagram first` in Postman

The browser's session is separate from Postman's session. The browser can successfully call `/me`, while Postman may not have the same session cookie. Do not assume Postman authentication works just because browser authentication works.

The callback was updated to fetch the authenticated profile using `/me` and store that ID in the session. The real publish subsequently succeeded, so do not restart debugging this old error unless it reappears.
